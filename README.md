# ThirdBrain — 세종시 정책 네트워크 플랫폼

세종시 행정체계를 **12개 정책 섹터**로 재구성하고, 전 분야의 정책을 **점(노드)** 으로,
정책 사이의 관계를 **선(엣지)** 으로 놓아 하나의 망으로 본다.
새 정책이 만들어지거나 시민 민원이 발생하면 해당 정책 노드에 **연결**되고,
그 순간 노드의 **크기가 커지며**, 문제가 겹치면 **붉게 전환**된다.
모든 정책은 섹터 → 대영역 → 시(市) 라는 **수렴축**을 따라 하나의 핵심점으로 모인다.

---

## 실행

```bash
node server.js
```

→ http://localhost:4173

의존성이 없다. `npm install` 이 필요 없고 Node 18 이상이면 바로 뜬다.
(브라우저에서 D3 v7 만 CDN으로 불러온다.)

## 12개 정책 섹터

세종시 본청 조직(11 실·국·본부 / 약 47과)을 **조직도가 아니라 정책 도메인 기준**으로 재구성했다.
조직 경계를 넘어 실제로 함께 움직이는 정책을 한 섹터에 모으는 것이 목적이다.
(예: 교육지원과 + 청년정책담당관 + 인구여성가족과 → `교육·청년·인구`)

| 대영역 | 섹터 | 주요 소관 |
|---|---|---|
| **공간·환경** | 도시공간·주택 / 교통·모빌리티 / 환경·녹지·기후 | 도시주택국, 교통국, 환경녹지국 |
| **경제·산업** | 경제·산업·일자리 / 농업·도농상생 / 문화·체육·관광 | 경제산업국, 도농상생국, 문화체육관광국 |
| **시민·복지** | 보건·복지 / 교육·청년·인구 / 안전·재난 | 보건복지국, 시민안전실, 소방본부 |
| **행정·거버넌스** | 행정혁신·디지털 / 재정·기획·균형발전 / 시민참여·소통·협력 | 자치행정국, 기획조정실 |

출처: [세종특별자치시 본청 조직도](https://www.sejong.go.kr/kor/sub01_010101.do)

## 시각 규칙 — 왜 이렇게 정했나

**색은 하나의 일만 한다.** 12개 섹터에 12색을 쓰면 색상 식별이 무너지고,
무엇보다 **위기 붉은색이 다른 색에 묻힌다**. 그래서 색의 역할을 나눴다.

- **색상(hue) = 4대 정책 영역** — 검증된 4색만 사용
- **섹터 = 명도 단계 + 공간 위치 + 라벨** — 색이 아니라 위치가 섹터를 알려준다
- **붉은색 = 상태(위기) 전용** — 섹터 색에서 적색 대역을 완전히 비웠다

4색(`#199e70` `#c98500` `#3987e5` `#ae55c1`)은 색각이상·명도대비 검증을 **전 조합 통과**했고,
위기 적색 `#d03b3b` 도 네 색 모두와 분리된다. 파랑↔보라 쌍만 색각이상 경계값(ΔE 6.3)이라
라벨·공간분리·범례라는 보조 식별수단을 함께 둔다.

**상태는 색만으로 전달하지 않는다.** 색 + 기호(`● ▲ ◆ ■`) + 맥동 애니메이션 세 가지를 함께 쓴다.
모션을 끈 환경에서는 정지된 경보 링으로 대체된다.

### 점의 크기

```
r = 6 + 1.2·√(정책비중) + 5.5·log₁₀(1 + 신호부하) + 0.9·√(횡단연결수)
신호부하 = Σ 심각도가중 × (1 + log₁₀(1 + 건수))
```

건수에 로그를 씌워 **한 건의 대규모 청원이 전체를 압도하지 않게** 했다.

### 상태 판정 — '위기'는 복합 실패일 때만

경보가 흔해지면 색이 의미를 잃는다. 그래서 단일 지표로는 위기를 주지 않는다.

- 진척 격차만으로는 최대 **미비·지연**까지
- **위기**는 다음 중 하나일 때만: 위기신호 2건 이상 / 위기+고심각 신호가 겹침 /
  위기신호 + 지연 + KPI 미달 / 지연 20%p 초과 + KPI 미달

현재 샘플 데이터 기준 59개 정책 중 **정상 27 · 주의 18 · 미비 9 · 위기 5**.

## 데이터 구조

```
data/
├── taxonomy.json   4대영역 · 12섹터 · 상태정의 · 연결유형   (분류체계)
├── policies.json   59개 정책 노드 — 예산·기간·진척·KPI·태그
├── links.json      75개 정책 간 관계 — 시너지 / 선후의존 / 상충
└── signals.json    30건 시민 신호 — 민원·위기·지적, 정책에 연결
```

**수렴축(정책→섹터→대영역→시)은 저장하지 않는다.** 분류체계에서 런타임에 자동 생성된다.

> ⚠️ 현재 데이터는 **예시(샘플)** 다. 정책명은 세종시 실제 의제를 참고했으나
> 예산·진척률·KPI·민원 수치는 구조 시연을 위한 가상값이다. 실제 운영 시 시청 내부 데이터로 교체해야 한다.

### 정책 노드

```json
{
  "id": "P0701", "sector": "S07", "label": "공공의료·종합병원 확충",
  "dept": "보건정책과", "budget": 88000, "start": "2021-01", "end": "2030-12",
  "progress": 0.34, "planned": 0.52, "weight": 10,
  "tags": ["의료공백", "시민불만"],
  "kpi": [{ "name": "병상 확보", "target": 1200, "current": 420, "unit": "병상" }]
}
```

`budget` 단위는 **백만원**. `dir: "down"` 을 KPI에 달면 낮을수록 좋은 지표(채무비율, 미세먼지)로 계산한다.

### 관계

| 유형 | 의미 | 선 모양 |
|---|---|---|
| `synergy` | 함께 추진하면 효과가 커짐 | 실선 |
| `dependency` | 앞 정책의 성패가 뒤 정책을 좌우 | 파선 |
| `conflict` | 예산·부지·목표가 부딪힘 | 점선 |
| `converge` | 수렴축 (자동 생성) | 가는 흰 선 |

## API

| 메서드 | 경로 | 설명 |
|---|---|---|
| `GET` | `/api/graph` | 분류체계·정책·연결·신호 일괄 반환 |
| `POST` | `/api/signals` | 시민 신호 추가 (`title`, `targets[]` 필수) |
| `POST` | `/api/policies` | 정책 추가 (`label`, `sector` 필수, `links[]` 동시 생성 가능) |
| `POST` | `/api/links` | 정책 간 관계 추가 |

쓰기 요청은 `data/*.json` 에 그대로 반영된다.

```bash
curl -X POST http://localhost:4173/api/signals \
  -H 'Content-Type: application/json' \
  -d '{"title":"버스 배차 불만","targets":["P0201"],"severity":"high","count":40}'
```

## 다음 단계

이 버전은 **구조가 성립하는지 확인하는 프로토타입**이다. 실전 투입 전 필요한 것:

1. **실데이터 연결** — 시정 4개년 계획 과제, 예산 편성, 국민신문고·새올 민원 데이터
2. **민원 자동 분류** — 접수된 민원 텍스트를 읽어 어느 정책에 붙일지 자동 제안 (현재는 수동 선택)
3. **시계열** — 지금은 현재 시점 한 장면. 분기별 스냅샷을 쌓으면 *망이 어떻게 변해왔는지* 가 보인다
4. **권한·계정** — 부서별 편집 권한, 변경 이력
5. **저장소 이전** — JSON 파일 → DB (동시 편집 시 파일 쓰기는 안전하지 않다)
6. **섹터 재검토** — 12개 구분은 조직 개편이나 시정 방향에 따라 조정 가능하다
