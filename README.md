# ThirdBrain — 세종시 12대 섹터 진단·공약 네트워크

「세종시 진단 12대 섹터 정리」의 **97개 진단**과 브리핑 계획표·공약자료집의 **54개 공약**을
하나의 망으로 잇는다. 배치는 **맞물린 두 개의 원환**이고, 두 원이 겹쳐 만드는
렌즈(vesica)가 곧 수렴점이다.

```
             ┌ 팀 166       가장 바깥
             ├ 과 76
바깥 궤도 ─┤ 진단 97  ○     문제는 바깥에 드러난다
             ├ 섹터 12
안쪽 궤도 ─┤ 공약 54  ◇     해법은 안에서 잇는다
             ├ 영역 4
렌즈 중심 ─┘ 세종시 1       모든 축이 여기로 수렴한다

총 410개 노드 / 662개 연결
```

왼쪽 원환 = 공간·환경·농업 + 경제·산업·기술 / 오른쪽 원환 = 시민의 삶 + 도시위상·문화·안전.

## 배치 두 가지 — 상단에서 전환

| | 배치 | 잘 보이는 것 |
|---|---|---|
| **좌우 고리** (기본) | **왼쪽 고리 = 진단 97 · 오른쪽 고리 = 공약 54**, 겹치는 렌즈에 시·섹터, 바깥 고리에 과·팀 | **문제와 해법의 대응**. 같은 섹터가 좌우 같은 높이를 쓰므로 마주 본다. 왼쪽이 두꺼운데 오른쪽이 얇으면 그게 곧 공약 공백이다 |
| **섹터 묶음** | 맞물린 두 원환, 섹터마다 진단·공약을 함께 | **섹터의 전체 모습**. 한 섹터의 문제와 해법이 한자리에 모여 있다 |

좌우 고리 배치는 **로고 그대로다**. 두 원이 크게 겹쳐 고리 한 바퀴를 다 쓰면
40%가 렌즈 안으로 파고들기 때문에, 노드는 바깥쪽 호(|t| ≤ 100°)에만 앉히고
배경 원은 완전한 형태로 남긴다. 그러면 서로 마주 보는 두 개의 C 자가 되고,
가운데 렌즈는 시(市)와 12섹터 자리로 비워진다.

전환하면 노드를 새 자리로 곧바로 옮기고 국소 정렬만 시킨다 —
400개가 화면을 가로질러 날아가면 전환이 느리게 느껴지기 때문이다.

### 선은 누르기 전까지 그리지 않는다

기본 화면은 **점만 있는 성좌**다. 노드를 누르는 순간 그 노드의 망만 드러난다.
662개 선을 늘 그리면 아무것도 읽히지 않기 때문이고, 덕분에 노드를 410개까지
늘려도 화면이 무너지지 않는다. 선이 숨겨진 동안은 선 계산 자체를 건너뛴다.

각 원환은 정확히 6개 섹터 = 2개 영역을 담는다. 겹침부(교점 ±126.9°)는 비워
렌즈를 살리고, 노드 좌표와 배경 도형이 같은 상수를 쓰므로 궤도와 정확히 맞물린다.

노드를 선택하면 연결된 노드가 **홉 거리 순서로 차례차례 점등**되고, 그때만 선이 나타난다.
1홉 0.105초, 2홉 0.210초… 순으로 빛이 번지고, 선을 따라 전류가 흐른다.

### 연결의 종류

| 유형 | 수 | 뜻 |
|---|---|---|
| `converge` | 409 | 팀→과→섹터→영역→시 로 모이는 수렴축 |
| `resolves` | 111 | 공약이 어떤 진단을 겨냥하는가 |
| `affinity` | 85 | **서로 다른 섹터에 흩어져 있지만 같은 문제를 공유하는 진단 쌍** (문자 유사도로 도출, 진단당 최대 2개) |
| `synergy` | 38 | 함께 추진하면 효과가 커지는 공약 |
| `dependency` | 16 | 앞 공약의 성패가 뒤를 좌우 |
| `conflict` | 3 | 예산·부지·목표가 부딪힘 |

## 배포 (Render)

저장소에 `render.yaml` 블루프린트가 있다. Render 대시보드에서
**New → Blueprint** 로 이 저장소를 고르면 그대로 뜬다.

```yaml
runtime: node · plan: free · startCommand: node server.js
healthCheckPath: /api/graph · READ_ONLY: true
```

### 공개 배포는 쓰기를 잠근다

`READ_ONLY=true` 면 모든 POST 가 403 이다. 누구나 접근하는 주소에서
아무나 진단·공약·신호를 밀어 넣게 두지 않기 위해서다.
대조(`/api/proposals/analyze`)는 열려 있어 화면에서 연결 지점 확인까지는 그대로 된다.
**입력이 필요하면 로컬에서** `node server.js` **로 띄워 쓴다** (로컬은 기본 쓰기 가능).

### 무료 플랜의 제약 두 가지

- 15분 무접속이면 잠들고, 다음 요청에서 **30~60초** 깨어나는 시간이 걸린다.
- 파일시스템이 휘발성이라 **재시작하면 `data/*.json` 변경분이 사라진다**.
  쓰기를 살리려면 유료 플랜 + 디스크를 `/opt/render/project/src/data` 에 붙여야 한다.

### 정적 호스팅을 쓸 때

서버 없이 올리려면 `node tools/build-static.js` 로 `dist/` 를 만들어
아무 정적 호스팅에나 올리면 된다. API 없이 `graph.json` 만으로 동작하고,
정책 입력은 브라우저에서 대조한 뒤 제안 파일을 내려받는 방식으로 바뀐다.

## 정밀 진단 — 97개 전수 채점

세종시는 특정 분야가 아니라 **전 분야가 동시에 취약한 구조**다.
그 판단을 주장이 아니라 수치로 만들기 위해 4축 평가모델로 97개 진단을 전수 채점했다.

### 4축 (각 1~5점)

| 축 | 묻는 것 | 가중 |
|---|---|---|
| **구조성** | 단년도 정책으로 해소되지 않는 구조적 결손인가 | 30% |
| **체감도** | 시민 생활에 직접·즉시 닿는가 | 25% |
| **악화성** | 방치하면 스스로 악화되고 다른 영역으로 번지는가 | 25% |
| **권한 결여** | 해법이 시 권한 밖(중앙·국회·타기관)에 있는가 | 20% |

**구조적 심각도 = 가중합 × 20** (0~100)

### 잔여위험 — 대응을 감안하고도 남는 위험

```
잔여위험 = 구조적 심각도 × (1 − 대응 감쇄) + 현장 신호 가산
대응 감쇄 : 공약 0건 0% · 1건 18% · 2건 30% · 3건 이상 38%
신호 가산 : min(12, 신호부하 × 0.6)
```

공약 하나가 구조적 문제를 다 없애지는 못한다는 전제를 감쇄율에 반영했다.

| 상태 | 잔여위험 | 색 |
|---|---|---|
| **위험** | 72 이상 | 크림슨 `#d42f37` |
| **경계** | 58~71 | 엠버 `#de602f` |
| **주의** | 44~57 | 골드 `#d4a73e` |
| **관리 가능** | 44 미만 | 세이지 `#628c6a` |

## 행정조직 연결

12대 섹터를 세종시 행정조직에 붙였다. 좌측 필터의 **소관 과 표시**를 켜면
각 섹터 바깥 궤도에 소관 과가 나타나고, 섹터를 선택하면 상세 패널에
국 → 과 → 팀이 계층으로 펼쳐진다.

| | 수 | 출처 |
|---|---|---|
| 국·실·본부 | 12 | **시 공식 조직도** |
| 과·담당관 | 59 (그래프 노드 76) | **시 공식 조직도 + 부서별 담당업무** |
| 팀 | 166 | **도출값** — 공식 조직도에 팀명이 공개돼 있지 않아 각 과의 담당업무에서 기능 단위로 나눈 것이다. 실제 팀명과 다를 수 있다 |

과가 여러 섹터에 걸치면 섹터마다 노드가 생겨 59과 → 76개 노드가 된다.
팀은 중복을 피해 과가 처음 등장한 섹터에만 매단다.

라벨은 배율에 따라 단계적으로 드러난다 — 기본 배율에서 244개(시·영역·섹터·진단·공약·과),
배율 0.55 이상에서 팀까지 **410개 전부**. 점 자체는 언제나 전부 그려진다.

과 → 섹터 배정은 담당업무 기준이며, 한 과가 여러 섹터에 걸칠 수 있다
(예: 지능형도시과 → 과학기술·디지털 + 도시 인프라).

## 신규 정책 입력

상단 **＋ 신규 정책** 으로 정책 니즈를 넣으면, 97개 진단과 대조해 연결 지점을 찾아
망에 편입한다. 자동 판정이 애매하면 저장만 하고 Claude Code 로 넘긴다.

```
정책 니즈 입력 → 망과 대조 → 연결 지점 확인(체크박스) → 편입
                     └ 애매하면 → data/inbox/<ID>.json → Claude Code
```

### 자동 연결 방식

형태소 분석기 없이 **문자 바이그램 Dice 유사도**로 진단·공약·섹터와 대조한다.
절대 임계값만 쓰면 표현이 다른 정책을 통째로 놓치므로, **최고 점수 대비 상대 기준**
(강한 일치 = 최고점의 45%, 최소 0.09)을 함께 둔다.

어림값이므로 자동 연결 결과는 **체크박스로 확인받은 뒤** 반영한다.
예를 들어 "읍면 순환 마을버스"는 "생활교통망 단절"과 함께 "디지털 격차 확대"도
끌어온다 — 두 진단이 모두 '읍면지역'을 담고 있기 때문이다. 이런 건 체크를 풀면 된다.

### Claude Code 로 넘기기

```bash
node tools/link-proposal.js                    # 대기 목록
node tools/link-proposal.js --show <ID>        # 전체 맥락 + 섹터/진단 후보
node tools/link-proposal.js --apply <ID> --sector S07 --resolves S07-02,S07-03
node tools/link-proposal.js --apply <ID> --auto   # 자동 분석 그대로 반영
```

`--show` 는 정책 원문, 섹터 후보 순위, 점수가 매겨진 진단 목록, 12대 섹터 전체를
한 화면에 출력한다. 그대로 판정 근거로 쓸 수 있다.

## 디자인 규칙

### 상태는 색이 아니라 '채움 밀도'가 먼저 말한다

모든 노드는 **속이 빈 링**이고, 안쪽 코어가 차오르는 정도로 위험을 읽는다.
색을 전혀 못 보는 상태에서도 상태가 그대로 읽힌다.

| 상태 | 코어 채움 | 색 |
|---|---|---|
| 관리 가능 | 20% | `#628c6a` |
| 주의 | 36% | `#d4a73e` |
| 경계 | 54% | `#de602f` |
| 위험 | 72% + 이중 링 + 맥동 | `#d42f37` |

### 모양 — 모두 원, 링 개수가 계층

모든 노드는 원이다. 마름모·사각 같은 다른 도형을 섞지 않는다.
대신 **링 개수**로 계층을 말하므로, 색을 못 봐도 무엇인지 구분된다.

| 계층 | 마크 |
|---|---|
| 팀 | 점선 링 하나 |
| 과 | 링 하나 + 작은 점 |
| **진단** | 링 하나 + **채움**(채움 밀도 = 상태) |
| **공약** | **이중 링** |
| **영역 · 시** | **삼중 동심원** |

시(市)는 모든 축이 모이는 최종 수렴점이라 반지름 40으로 가장 크게 둔다.

### 강조 — 특정 섹터의 솔루션

`taxonomy.json` 의 `highlight` 로 한 섹터의 공약을 따로 부각한다.
현재는 **④ 문화·예술·도시정체성의 공약 5개**를 오렌지 `#f7511f` 에 반지름 30 으로 둔다.
시(市, 40) 다음으로 크고, 다른 공약(최대 23)·진단(최대 26)보다 크다.

```json
"highlight": { "sector": "S04", "level": "pledge", "color": "#f7511f", "radius": 30 }
```

**점등되면 꽉 찬다.** 다른 노드는 클릭으로 켜지면 블루로 물들지만, 강조 노드는
제 색을 지키면서 속이 오렌지로 가득 찬다 — 링만 남는 다른 점들과 한눈에 갈린다.
섹터 ④를 눌러도, 강조 노드 자신을 눌러도, 다섯 개가 함께 채워진다.

`sector` 만 바꾸면 다른 섹터에 그대로 옮겨 붙는다.

> 오렌지는 골드 램프와 **정상시각 ΔE 17** 로 갈리지만, **적록색각이상에서는 ΔE 5.2** 에
> 그친다. 오렌지와 골드는 같은 축의 이웃이라 어떤 오렌지를 골라도 이 한계는 남는다.
> 그래서 **크기**가 실질적인 구분 채널이다 — 색을 못 봐도 가장 큰 점 다섯 개로 읽힌다.

### 색 — 연결 얽힘도를 말한다

| 역할 | 색 |
|---|---|
| **얽힘도 램프** | `#605f5c` 그레이 → `#f0bb3b` 골드, 7단계 |
| **연결(점등)** | `#43acfb` — 노드를 누르면 연결된 것이 블루로 물든다 |
| **위험** | `#c4cbd4` 실버 |

램프는 **연결 얽힘도**를 말한다. 얽힘이 적으면 무채색 그레이로 물러나고,
얽힐수록 채도가 자라 골드에 가까워진다. 명도가 단조 증가하므로
색을 전혀 못 봐도 밝기만으로 순서가 읽힌다.

```
얽힘도 = 의미관계 연결 수 + 0.5 × 섹터를 넘는 연결 수
```

수렴축은 구조라 세지 않는다. 정책층(진단·공약) 안에서 백분위를 내 7단계에 태우고,
구조층(섹터·영역·시·과·팀)은 자기 위상에 맞는 단계를 고정으로 준다.

**크기와 색은 서로 다른 것을 말한다.** 크기는 우선순위(지금 급한가),
색은 얽힘도(얼마나 물려 있는가). 작지만 골드인 점은 *덜 급하지만 많이 얽힌* 지점이다.

노드 라벨은 **`값:이름`** 형식이다(`91:상급종합병원 부재`, `1:언론협력팀`).

> **위험색이 왜 실버인가.** 골드를 기조로 삼으면 붉은 계열은 적록색각이상에서
> 골드와 겹친다 — 순수 적색은 ΔE 2.0, 크림슨 핑크도 8.9에 그쳤다.
> 무채색 실버는 램프 전 단계와 **ΔE 15.5 이상** 떨어지고 연결 블루와도 18.1 분리된다.
> 색을 못 보는 사람에게도, 보는 사람에게도 가장 확실한 경보다.

### 점의 크기 = 우선순위 · 도시발전 영향력

크기는 '연결이 많은가'가 아니라 **'지금 중요한가'** 를 말한다.

**진단** `0.55 × 잔여위험 + 0.30 × 구조적 심각도 + 15 × 파급도`
 · 잔여위험 — 지금 급한가
 · 구조적 심각도 — 구조를 흔드는가
 · 파급도 — 다른 섹터의 문제까지 물고 있는가 (섹터를 넘는 연결 수, 5개에서 포화)

**공약** `0.19 × 걷어내는 위험 총량 + 18 × 선행성 + 2 × 비중`
 · 걷어내는 위험 총량 — 겨냥한 진단들의 심각도 합
 · 선행성 — 이 공약이 다른 공약의 선행조건이 되는 횟수

**섹터** `0.6 × 평균 잔여위험 + 4 × 위험 진단 수`

계층 안에서 순위백분위를 내고 **세제곱 곡선**(`pct^2.6`)으로 눌러 크기를 매긴다.
상위 소수만 눈에 띄게 커지고 나머지는 작게 남는다 — 진단 97개 중 반지름 16 이상은 24개뿐이다.

| | 최대 | 중앙 | 최소 |
|---|---|---|---|
| 진단 반지름 | 26 | 9.7 | 6.5 |
| 공약 반지름 | 23 | — | 7 |

과·팀은 정책이 아니라 구조라 크기를 고정한다(7.5 / 4.6).

### 연결선 — 얇게, 굵기에 의미를 싣지 않는다

선은 **관계가 있다는 사실만** 알리면 된다. 굵기로 무언가를 전달하려 하면
읽는 사람이 없는 규칙을 찾게 되므로, 육안으로 보이는 최소 두께의 실선으로만 긋는다.

```
수렴축 0.5 · 연관 0.7 · 해소 0.9 · 시너지/의존 1.0 · 상충 1.1 · 점등 시 1.4  (px)
색     = 양끝 노드 색을 잇는 그라데이션 (연결되면 양끝이 함께 블루로)
```

관계 유형(선후의존·상충)은 파선·점선 **중심선**을 덧그려 구분한다.

## 로고

맞물린 두 원과 그 겹침에서 생기는 렌즈 — **둘이 만날 때 비로소 생기는 제3의 공간**이 곧 Third Brain이다.
화면의 기하(두 원환 + 중앙 렌즈 수렴점)를 그대로 마크로 압축했으므로 제품과 로고가 한 체계다.

```
public/img/logo.svg        골드 그라데이션 정본
public/img/logo-mono.svg   단색(currentColor) — 인쇄·워터마크용
public/logo.html           브랜드 시트 (크기별·배경별·색·사용 규칙)
```

- 마크는 정사각 viewBox 48×48, 최소 사용 크기 16px
- 워드마크는 **Third**(보조색) + **Brain**(본문색)으로 굵기를 나눈다
- 두 원의 간격과 굵기는 바꾸지 않는다 — 겹침이 로고의 뜻이다
- `logo-mono.svg` 를 `<img src>` 로 넣으면 색이 상속되지 않는다. **인라인**으로 넣을 것

브랜드 시트: http://localhost:4173/logo.html
